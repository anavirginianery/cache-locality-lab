Experimento: tres niveis de stack distance com 1 milhao de requisicoes

gerado em 27/09/2026 12:02 1.000.000 requisições por cenário dmax = 10.000 objetos novos = 5,0% semente = 7

Cada cenário foi gerado a partir de uma distribuição de stack distance conhecida. Como a distribuição é conhecida, todo valor medido na carga tem um valor teórico correspondente, calculado sem simular nada. As linhas dos gráficos são o medido; os círculos vazados são o teórico. Se os dois coincidem, a carga saiu como foi pedida.

As curvas são de hit rate: a fração das requisições atendidas por um cache LRU de cada tamanho. O valor teórico vem direto da distribuição de stack distance, por hit(C) = (1 − P(∞)) · P(d < C) — acerta quem é reúso e cuja stack distance cabe no cache.

Curva de hit rate

SD baixa (β = 1,5) SD media (β = 1,0) SD alta (β = 0,5)

Quanto mais alta a curva, melhor o cache se sai. A carga de SD alta precisa de um cache muito maior para chegar ao mesmo hit rate das outras. O eixo vai até o tamanho da carga, 1.000.000 requisições, para mostrar a curva inteira: das três, nenhuma passa de 1 − P(∞) = 95,0%, porque objeto novo nunca pode ser acerto. Da vertical tracejada (dmax = 10.000) para a direita a curva é plana — nenhum reúso tem stack distance maior que dmax, então aumentar o cache além disso não acerta nada novo.

Lê-se assim: no ponto x, a curva diz qual porcentagem dos reúsos tem stack distance menor que x — ou seja, quantos reúsos caberiam num cache de x objetos. O eixo vai até o tamanho da carga; as três chegam a 100% em dmax = 10.000 e ficam lá, que é a mesma informação do trecho plano da curva de hit rate.

As faixas dobram de tamanho a cada passo (1, 2, 4, 8, …), porque a stack distance varia por ordens de grandeza.

Footprint

SD baixa (β = 1,5) SD media (β = 1,0) SD alta (β = 0,5)

Quantos objetos distintos aparecem numa janela de N requisições — os dois eixos em escala log. O valor é exato, não amostrado: é a média sobre todas as janelas daquele tamanho, então não depende de semente. A janela vai de 1 requisição até a carga inteira. Nos dois extremos a curva é forçada: em 1 requisição o footprint é 1 objeto, e na janela do tamanho da carga ele é exatamente o número de objetos distintos da tabela acima. É esse o "footprint em um número só" da carga — o resto da curva é o caminho entre os dois extremos, e é ali que os cenários se separam. O footprint não é um parâmetro do gerador: ele emerge do nível de stack distance. A stack distance de um reúso é, por definição, a contagem de objetos distintos na janela entre dois pedidos ao mesmo objeto; então reúsos longos significam janelas com muitos objetos distintos. As duas curvas descrevem a mesma localidade por ângulos diferentes.

A última coluna é a resposta para "esta carga tem stack distance alta?" no único jeito que faz sentido: em relação ao tamanho de cache que você vai usar — a fração dos reúsos com SD menor que o cache, isto é, os que cabem. O mesmo valor de stack distance é alto para um cache pequeno e baixo para um grande. A fração complementar, dos que não cabem, está em conferencia.csv.
